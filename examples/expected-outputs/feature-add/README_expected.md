入力: `examples/sample-minutes/feature-add-sample.md`

生成フェーズ: Step 3 まで（実装は含まない）

## 想定した設定

- プロジェクト名: サンプル在庫管理システム（機能追加）
- 依頼内容: CSV エクスポート機能追加 + 在庫フィルター改修
- 依頼者: 鈴木部長（メール）
- 期限: 2週間以内（〜2026-06-29）

## このサンプルで確認できること

1. **impact-analysis.md**: 既存コードへの影響範囲が洗い出されているか
2. **02-functional.md**: 既存機能の変更点と新機能が明確に区別されているか
3. **03-open-questions.md**: CSV の列定義・フィルターの保存要否等のQ が登録されているか
4. **04-integrated.md**: 既存テーブル構成を変えないという制約が反映されているか
5. **SKILL.md**: 機能追加固有のルール（サーバーサイド生成・既存パターン踏襲）が記載されているか

## 評価基準

- 影響を受けるファイルが 10件以内に収まっていること（超える場合は Q として確認）
- 「既存のテーブル構成は変えない」という制約が全ドキュメントに反映されていること
- CSV エクスポートのサーバーサイド生成（大量データ対応）の理由が ADR に記載されていること
- フィルター UI が既存パターンを踏襲することが設計ドキュメントに明記されていること
