> プロジェクト固有の禁止事項・業務ルール・API 仕様を記載する。

## プロジェクト概要

- クライアント: 株式会社サンプル商事
- システム: 拠点別在庫管理システム（Next.js 15 + Supabase + Vercel）
- ユーザー: 管理者 2名 + 在庫担当 3名 = 計 5名

---

## 禁止事項（絶対に変更しないこと）

### ロール定義（変更禁止）

```typescript
type UserRole = 'admin' | 'staff'
```

- `admin`: 全機能 + 在庫金額情報の閲覧権限
- `staff`: 入出庫・商品検索（在庫金額情報は閲覧不可）
- 第3のロールを勝手に追加しない

### 在庫金額の表示制御（変更禁止）

- `単価 (unit_price)` カラムは `staff` ロールには表示しない
- `在庫金額 (unit_price × quantity)` の計算結果も同様
- Supabase の RLS で列レベルセキュリティを適用する

### 拠点マスター（初期値変更禁止）

初期データとして以下の3拠点を投入する:

```
本社 (headquarters)
倉庫A (warehouse_a)
倉庫B (warehouse_b)
```

拠点の追加は管理画面から行う。コード内にハードコードしない。

## 業務ルール

### 入出庫登録

- 在庫数がマイナスになる出庫は登録前にバリデーションエラーとする
- 入出庫の記録は削除不可（論理削除も不可）。修正は「修正入庫/出庫」として新規登録する
- 入出庫の備考は必須ではないが、推奨ラベル（入庫理由等）を UI に表示する

### 在庫アラート

- アラートは在庫数が閾値「以下」になったタイミングで発火する（「未満」ではない）
- 同一商品に対して1日に複数回アラートを送らない（Edge Function でデバウンス）
- 閾値 0 はアラート無効として扱う

### CSV インポート

- インポート前にドライランモードで件数・エラーを確認する UI を必ず挟む
- エンコードは UTF-8 BOM なし を基本とし、BOM あり（Excel デフォルト）も受け入れる
- インポート中にエラーが1件でもあればロールバックする（all-or-nothing）

---

## DB 設計ルール

- 全テーブルに `created_at`, `updated_at` カラムを必ず設ける
- 全テーブルに RLS を有効にする（無効にすることは禁止）
- 論理削除は `deleted_at` カラムで管理する（`is_deleted` フラグは使わない）
- マイグレーションは `packages/db/migrations/` に格納し、番号を連番管理する
