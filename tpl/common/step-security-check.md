# 共通: セキュリティチェック

実装完了後、報告前に必ず実施する。

## 実行内容

1. ECCの differential-review スキルを使ってこのセッションのコード変更をセキュリティレビュー
   ```
   /superpowers:differential-review
   ```
2. 検出された問題を全て修正
3. 再実行して 0件になることを確認
4. 0件になったら次Step(報告)に進む

## チェック項目(最低限)

- SQLインジェクション
- XSS
- 認証バイパス
- 認可漏れ
- 秘密情報のハードコーディング
- 秘密情報のログ出力
- 危険なAPI使用(eval等)
- 依存関係の脆弱性

## 0件にならない場合

問題が残る場合、以下を明示してユーザーに判断を仰ぐ:
- 残存する問題一覧
- 各問題の深刻度
- 修正しない場合のリスク
- 本リリースで対応 / 次リリースに持ち越し の判断

**自動的に残存させてはならない**。必ずユーザー確認を取る。

## 禁止事項

- セキュリティチェックをスキップして報告
- 「動いているから大丈夫」で問題を無視
- チェック結果を報告書に含めない
