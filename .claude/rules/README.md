# .claude/rules/ — ルール 3 階層構成

Claude Code が読み込むルールを 3 階層に分離する。

## 階層構成

```
.claude/rules/
├── common/          ← スタック非依存の共通規約（全プロジェクトに適用）
│   └── coding-standards.md
├── stack/           ← スタック固有ルール（該当プロジェクトのみ適用）
│   ├── supabase.md
│   ├── vercel.md
│   ├── aws.md
│   └── firebase.md
└── project/         ← プロジェクト固有ルール（各プロジェクトが管理）
    └── (各プロジェクトが独自に追加)
```

## 適用ルール

| 階層 | 誰が書く | いつ読む |
|------|---------|---------|
| `common/` | ベースリポジトリ | 常時 |
| `stack/` | ベースリポジトリ | 該当スタック使用時 |
| `project/` | 各プロジェクト | 常時（プロジェクト固有） |

## common/ の原則

- スタック名（Supabase, Vercel, AWS, Firebase 等）を出してはならない
- 「どの技術を使っても当てはまる」内容のみ記載する
- スタック固有の話は `stack/` に書く

## project/ の原則

- ベースリポジトリは `project/.gitkeep` のみ管理する
- 各プロジェクトが `project/` に独自ルールを追加する
- ベース更新時に `project/` の内容は上書きしない

## 新しいスタックを追加するとき

1. `stack/新スタック名.md` を作成
2. 「禁止事項」セクションを必ず含める
3. `CONTRIBUTING.md` の手順に従って PR を出す
