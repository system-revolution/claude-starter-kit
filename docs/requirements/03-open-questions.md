# 03. 未確定事項 (Open Questions)

> 議事録・背景目的・機能要件の各段階で発生した未確定事項を Q-xx 形式で管理する。
> **これはプロジェクト進行中に最も重要なファイルの一つ**。

## 原則

1. 未確定事項は必ずここに記録する
2. 仮値で進める場合、影響する全ファイルに `# TODO: Q-xx 確定後に更新` コメントを入れる
3. Q-xx が解決したら Resolved 表に移動し、影響ファイルを全て更新する
4. ステータス昇格(tentative → confirmed)は必ず顧客合意が必要。SE 判断だけで確定にしてはならない

## カテゴリ一覧

- 認証・権限
- 外部連携
- データ移行
- 非機能要件(SLA/性能/ログ)
- スコープ
- セキュリティ
- コスト・契約

## ブロッキング度の定義

| レベル | 定義 |
|-------|------|
| 高 | これが決まらないと設計全体が進まない |
| 中 | 該当機能の設計が進まない |
| 低 | 仮値で進めて後から変更可能 |
